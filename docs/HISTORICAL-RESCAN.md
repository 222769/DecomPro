# Rescan equipment from previous decom spreadsheets

Trolley rescan can find complete equipment records in previous Excel files even when that work happened before DecomPro. This is separate from serial-recognition training and the bulk equipment importer.

1. Sign in to the intended workspace and choose the physical target trolley through Change trolley.
2. Enable Trolley rescan and choose Load previous decom Excel. Load the original .xlsx file, such as Decom May 26 - Collected. Loading the same file name replaces its previous lookup rows; other loaded files remain.
3. Scan or type a serial, asset number, barcode or security etch. Saved register items take priority. Otherwise exact matches in loaded historical files bring up the full source record. Multiple source matches require choosing a spreadsheet row. Pattern recognition does not invent historical identifiers.
4. Review and edit the copied equipment details. View original spreadsheet information shows all eleven original supplier fields, the file name, worksheet and row. The new item uses the chosen current disposal date and the currently signed-in technician; original date and disposal initials remain in the source preview and lookup data.
5. After reviewing the physical item and details, press Enter to confirm the check and add it, or tick the physical-check confirmation and select Add to current trolley. The first Enter searches; the next Enter confirms the displayed result. After success, the identifier clears and receives focus for the next scan. Multiple matches require selecting the correct source record first. Only this item is added. It uses the normal version-checked Firebase create path when connected, or the local register when working locally. Existing equipment, recognition training and paused normal scans remain unchanged.

Locally loaded lookup files stay private in this browser's workspace and are included in workspace JSON backups. Administrators can now explicitly share a loaded file with the private team archive; see [Interface and recovery update](INTERFACE-AND-RECOVERY-UPDATE.md). It is not bundled into the public website or uploaded as recognition training. A local import alone is not shared; the separate administrator sharing action publishes equipment lookup rows to Firestore. On another signed-in device, rescan searches the published team archive automatically; unshared files still need loading on that device or restoring from an appropriate workspace backup. Confirmed equipment is shared through the normal Firebase register. Sign-in to a different workspace identity clears the active lookup library; preserved local workspace data can still be recovered through the existing local-workspace switch.

Only the equipment fields used by DecomPro are retained; unused financial columns are ignored. Historical asset formats and leading zeros are preserved. Missing equipment fields appear as N/A for review; the new disposal date must be valid. Files are limited to 10 MB and 5,000 rows per import, with up to 20,000 lookup rows in a workspace. If more than 100 historical rows share a scanned identifier, use a more specific identifier.

Before confirming, DecomPro refreshes the shared register, checks for duplicate scanned identifiers, serials and assets, and checks that the target trolley is open and in the active collection. Server transactions enforce serial uniqueness and trolley status. A failed save keeps the preview for retry; a repeated scan after a confirmed save retrieves the existing register item rather than creating another. The private team archive and shared recovery require the updated Firestore rules described in that guide; a Blaze plan is not required for these client/Firestore operations.
