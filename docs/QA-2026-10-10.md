# DecomPro verification — 10 October 2026

## Repairs

- Local equipment removal now commits browser storage before changing the visible register. A full or unavailable storage write reports failure and preserves both inventory and the unfinished scan.
- Equipment editing uses the item ID, Firebase client and version captured when the editor opened. While saving, controls and cancellation are locked; repeated submissions are ignored. Failures leave the form available for correction.
- Restoring a workspace clears the previous register search, missing-detail filter, trolley scope, bulk selection and collection-review filters, and opens the restored inventory.
- The desktop sidebar scrolls on shorter displays. The account panel no longer covers the Admin action.
- Bulk-move test selectors target the exact destination field. Loading-failure tests also match development asset URLs carrying cache timestamps, so failures are actually injected.

## Validation

- Browser suite: 72 passing tests covering scanning and skips, asset formatting, spreadsheet recognition and reviewed corrections, editing, local storage failure, backups/restoration, shared connections, permission failures, trolley moves and history, readiness, collection handovers, PDF and supplier Excel exports, collection review, session summaries, administration UI and startup recovery.
- Unit suite: 32 passing tests.
- Firestore emulator suite: 15 passing tests, including membership isolation, duplicate prevention, concurrent edits, immutable audit history, locked trolley contents and atomic six-trolley collection.
- Authentication/Functions emulator suite: 9 passing tests covering administrator authorization and account lifecycle.
- Production build: successful. Existing large optional Excel/Firebase bundle warnings remain.
- Production build smoke checks: desktop 1280px and phone 390px layouts; dark appearance; startup; actual PDF and Excel downloads; leading-zero serial preservation; unfinished scan preservation. No JavaScript errors or failed asset requests observed.

Commands: `npm test`, `npm run test:unit`, `npm run test:database`, `npm run test:accounts`, `npm run build`. Emulator runs used the environment's existing emulator cache. Browser tests use Chromium.

## Verification limits

The execution environment blocks HTTPS access to `decompro.hxali.com` with a proxy 403, so the public deployment was not verified directly. Tests used the repository and built distribution, synthetic browser workspaces and Firebase emulators; no college equipment or team accounts were modified. Mobile checks use Chromium viewport emulation, not physical iOS Safari or scanner hardware. Account Cloud Functions were tested in emulators; their live deployment remains parked pending Firebase Blaze. Passing these checks demonstrates the tested workflows, not the absence of every possible bug.
